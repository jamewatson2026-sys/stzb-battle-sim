# 未雨绸缪 修复记录（2026-10-21）

> 用户报障（m01313）两条：
> ①「未能使下一次造成谋略伤害的战法再次发动」；
> ②「战法描述缺一条：该战法造成的谋略伤害无视目标 x% 的谋略属性（受谋略属性影响），在战报中也没有体现」。

## 一、官方原文（9.2.2 热更覆盖层 `tb_cfg_skill` 200301）

```
下回合开始后，@2@回合内自身下一次造成策略伤害的主动战法发动后可再次发动一次（跳过准备回合），
造成原战法#subsk_210301_effect_01#%的伤害和恢复效果，
该战法造成的伤害无视目标#subsk_211301_effect_01#%的谋略属性（受谋略属性影响）
```

覆盖层写盘为 8 字节 XOR（`KEY=8e509fe8596791fb`，`plain[i]=enc[i]^KEY[i%8]`），解密后按 UTF-16LE 抽取。
覆盖层 detail 表 spec 漂移（`parse_rows` 抛 IndexError），改用「detail_id 的 `<i` 字节 + objHdr=43 + 字段合理性」定位：

| detail | effect_id | 关键字段 | 换算 |
|---|---|---|---|
| `21030101` | 111（额外参数） | `effect_param 21030102`、`init_effect_ratio 50`、`constant_param 50` | 再发动 = **50%** |
| `21130101` | 161（无视敌方属性） | `constant_param 18000`、`intel_param 30000` | 谋略 80 → **30.0%**，成长 **0.15/点** |
| `20030101` | 122（子技能容器） | `constant_param 210301` | 子技能族 |

机制 161 的量纲锚点 = 击势（`21186301` `constant_param 60000` ↔ 官方「无视敌方 60% 防御属性」）⇒ 除数 **1000**；
未雨绸缪 = `(18000 + 0.4×30000) / 1000 = 30.0%`，成长 `30000/200/1000 = 0.15/点`。

## 二、根因

`src/engine/action.ts` 的 `triggerRepeatStrategy()` 只用**顶层**判定与改写：

```ts
if (!outputs.some((o) => o.kind === 'strategy_damage')) return;   // 旧
```

全注册表递归扫描（`scripts/_scan_weiyu.mts`）：带策略伤害的主动战法 59 个，顶层 56，**伤害嵌在子树里的 3 个**：

- `guangwu_zhongxing`（光武中兴）：`random_pick.options` → `combo_tag.outputs` → `strategy_damage`
- `daoxing_xianzu`（道行险阻）：`schedule_strike.output` → `strategy_damage`
- `zhiren_daishi`（二类指挥，不在本路径）

⇒ 这三类「造成策略伤害的主动战法」永远不会再发动 —— 正是报障 ① 的现场。
（另有一半原因：机制 161 在引擎里其实早有 `ignoreStrategyPct/GrowthRate`，但数据侧没挂、战报与描述都没体现 ⇒ 报障 ②。）
