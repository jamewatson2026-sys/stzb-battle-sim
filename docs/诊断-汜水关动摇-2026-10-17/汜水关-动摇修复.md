# 汜水关「动摇」误挂「恐慌」修复（2026-10-17）

## 现象

用户报障（原话）：

> 汜水关有bug，汜水关造成的是物理持续性伤害动摇，但是却挂成了恐慌

战报里汜水关施加的是 `panic`（恐慌），跳伤按**谋略 DoT** 结算（谋略 × 0.25），
与官方「动摇、每回合产生逃兵（伤害率 130%）、物理持续伤害」不符。

## 根因

两层叠加：

1. **数据层**：`src/data/skills.ts` 的 `sishuiguan` 把「动摇」直接写成 `status.type: 'panic'`，
   注释还写着「仓库既有口径：动摇 → panic」。同批「动摇」战法（险途暗渡 / 游击 / 浴血 /
   雪奋短兵 / 威震逍遥 / 九变之利）也沿用了这条映射。
2. **引擎层**：`src/engine/action.ts` 的 `computeDotTickDamage` 对所有 DoT 一律传
   `damageType: 'strategy'`；`src/engine/formulas.ts` 的 `calcDamage` 对 `isDot` 只实现了
   「兵力基础 ×1/3 + 谋略基础 ×0.25」，没有物理 DoT 的攻击基础 ×0.4 分支。

结果：即使把类型改掉，伤害仍会按谋略结算，所以必须同时补引擎口径。

## 口径（本次钉死）

- **动摇 `unrest` = 物理 DoT**：兵力基础 ×1/3（普通攻击的 1/3）+ **攻击 ×0.4（无随机）** × 伤害率 +
  攻防差主要伤害；吃「攻击伤害」类增减伤与兵种克制减伤。
- **恐慌 `panic` / 燃烧 / 妖术 = 谋略 DoT**：原口径不动。
- **袭屯夺气保持 `panic`**：官方原文写的是「恐慌」，不因为仓库曾把二者混用就改。
- 触发型动摇字段（`triggerOnBasic` / `charges` / `ignoresEvasionOnTick` / `clearBuffsOnTick` /
  `undispellable`）迁到 `unrest`；`triggerOnAttrDown`（袭屯夺气）继续只属于 `panic`。

## 交互收口

- 物理 DoT 会走 `applyDamage(damageType:'physical')`，因此：
  - 受击类钩子（舍身卫主 onHurt 等）按用户既有口径**吃全部伤害类型**，保持触发；
  - `selfPhysBoost.onDealPhysical`（造成攻击伤害后叠层）与「忠克猛烈」追加攻击已加 `!hit?.dotType`，
    避免把「动摇逃兵」误算成「攻击伤害」。
- 普攻触发动摇（威震逍遥）的规避判定仅对 `triggerOnBasic` 生效；
  `ignoresEvasionOnTick` 时不消耗规避层数。
