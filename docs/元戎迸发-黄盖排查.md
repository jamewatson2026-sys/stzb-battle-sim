## 三、判定

1. **不是黄盖专属 bug**：前锋站位下，黄盖的追击主战法能正常吃到额外目标，且额外目标拿到**完整效果**（挂上同倍率燃烧）。
2. 2026-10-15 当时「看起来没生效」只发生在**攻击距离内没有第二个敌人**时（中军 / 死士 / 单敌，即 §二 ②③④）——
   当时的实现把「本次命中目标」排除在额外目标池之外，这几类情形一律落空。
   **2026-10-17 起目标池含本次命中目标**（§六）：②③④ 两种站位/兵种与单敌场景都能**额外完整结算一次（打在同一目标上）**。
3. 标记仍按「触发即移除」**一次性消耗**，本场后续回合不会补发；现在只有「本次命中目标已被打死、且攻击距离内再无存活敌军」时才会选不到目标。

## 四、口径缺口的处置（用户 2026-10-15 拍板）

1. **未限定「主战法」→ 已修**。官方写「首次发动追击**主**战法时」，原实现只按状态类型查标记：
   主战法追击判定失败、同次普攻里**装配追击**先发动时，会由装配追击提前吃掉这次额外目标。
   现 `triggerPursuitSkill` 增加「仅追击主战法可消费」判定（`isMainPursuit = general.mainSkillId === skill.id`）。
   - 契约测试（`tests/treasure_mechanics.test.ts` 新增 describe「宝物 · 迸发（元戎）：额外目标只在追击主战法消费」，3 例）：
     ① 装配追击先发动 → 只打命中目标、**标记保留**；② 主战法追击发动 → 额外选取攻击距离内 1 个目标、标记移除；
     ③ 同次普攻内其后的追击恢复单目标（标记一次性）。
   - **红/绿取证**：把该判定临时改回 `true`（= 还原修复前行为）→ 第 ① 例失败
     `expected [ 'e2', 'e1' ] to have a length of 1 but got 2`（装配追击吞掉了标记）；恢复修复 → 全绿。
   - 回归：`npx vitest run` = **89 文件 / 823 用例全过**；golden 快照字节一致（T1~T9 固定集不佩戴宝物，
     宝物阶段只在佩戴时发事件）；上面六场景实测行为不变（①⑤⑥ 仍两目标、②③④ 仍单目标）。
2. **无可用目标也消耗标记 → 保持现状**：官方未写明「当场没选到目标是否保留到下次」，本次不动。
   2026-10-17 起目标池含本次命中目标（§六），只有「命中目标已被打死、攻击距离内再无存活敌军」时才会无可用目标；
   若要改成「选到目标才消耗」，再开一轮。

## 六、2026-10-17 修订：额外目标池含本次命中目标

**用户口径（原话）**：「元戎效果修复，首次追击战法发动以后额外选取攻击距离内的目标再次释放追击，修改效果为两次追击战法可以是同一个目标」。

对齐时拍板的两点（`ask_user_question` 结果，已写进实现）：

1. **形态 = 同一次发动 + 额外目标**：仍只有一条 `skill_cast`、一行「发动」，追击发动次数计 **1**，
   追击后联动（`triggerAllyRecastCommands` / `triggerActHooks` / `triggerCastKindHooks`）也只按一次触发。
   另一条路（独立第二次发动、战报两行）**未采用**。
2. **目标池 = 攻击距离内全部存活敌军随机 1 个，含本次命中的目标**：多敌时可能重复（3 个都在距离内约 1/3 概率打同一个），
   单敌 / 攻击距离 1（死士）稳定额外完整结算一次。官方只写「额外选取攻击距离内 1 个**目标**」，未排除已命中的那个。

### 代码改动（1 行 filter）

`src/engine/action.ts` 的 `triggerPursuitSkill`：

```ts
// 旧：本次命中目标被排除 → 单敌 / 攻击距离 1 / 中军站位时选不到目标、迸发落空
const candidates = enemies.filter((e) => e.alive && e !== hitTarget && distanceBetween(ctx, unit, e) <= range);
// 新：选取池 = 攻击距离内全部存活敌军，含本次命中的目标
const candidates = enemies.filter((e) => e.alive && distanceBetween(ctx, unit, e) <= range);
```

### 机制备注（同目标重复对结算的影响，如实记录）

- `executeSkillOutputs` 的 `pool` 缺省＝`targets`，战法段按目标逐个结算 → 同一目标出现两次 = **该段完整跑两遍**：
  DoT 走同源刷新（不叠层，燃烧仍是「214% 持续 2 回合」一份）；烈火焚舟的 `detonate` 段第二次施加前会**引爆**
  第一次挂上的燃烧（`inflict_status` 内先结算剩余跳伤），因此同目标复打上限更高。
- 自带 `targetMode` / `targetSide` 的输出不吃重复项（自己重选池）；`heal` 段按 `pool` 逐目标结算
  （`src/engine/action.ts:8412-8457` 的 `case 'heal'`），追击自带的自愈段（攻心等）按目标数恢复，重复目标不会额外回血。
- 战报文案未改：`src/engine/report.ts:156-158` 与 `web/battleView.ts:509-516` 都是 `targetIds.join('、')`，
  选中同一目标时自然显示两个相同名字 —— 这是「额外目标可以是同一个」的可视化结果，不需要新事件。
