# 鲁肃「减伤无法叠加」报障取证（2026-10-17）

用户报障（m00638）：`刚刚测试的时候发现鲁肃的被动战法减伤无法叠加？或者是与避其锋芒冲突了？`
截图现场：XP周瑜 / 鲁肃 各出现 `❌ 减伤冲突，数值取较高 0.05`，同一次触发里「造成的伤害提高 3%」正常挂上；陆逊成功获得「减伤 0.03」。

## 结论

**不是与【避其锋芒】冲突**（它是指挥战法，`sourceSkillType = command`，与被动【同仇敌忾】跨战法类型不判定冲突）。
真正吞掉层数的是**宝物词条【济世】**：它每触发一次恢复就挂一条 `damage_reduce 0.05`（`treasure:affix:济世` 前缀），
而 `inflictStatusCore` 的冲突豁免**只做了单向** —— 宝物/陈寿作为「施加方」跳过冲突，作为「既有状态」却仍进 `sameType` 候选，
于是【同仇敌忾】新挂的 0.03 被判「减伤冲突，数值取较高 0.05」直接丢弃。

## 口径追认 + 落地（用户 2026-10-17 m00894，已实现）

原「遗留」问题（济世每层永不衰减、恢复 N 次 = N×5%）**已由用户定口径**：
> 「可无限叠加，下一次受到伤害后清空，所有下一次都是这种情况，只覆盖一次攻击。」

- **语义**：可**无限叠加**（不设 `maxStacks`）；受到**下一次**伤害后**全部清空**（那一次伤害仍吃满所有层数）——只覆盖一次攻击。
- **实现**：`damage_reduce` 新增 `consumeOnHurt?: true`（`src/engine/types.ts` 的 create / runtime 两处）；`applyTreasureHealOnTarget` 施加模板带上该标记；
  `applyDamage` 扣兵后调 `consumeNextHitReduce`（`src/engine/action.ts`，与奉令护蜀 `consumePendingStacks` 同型，逐层发 `status_expired`）；
  `pushStatus` 的 detail 改为「减伤 5%（可叠加，下一次受到伤害后失效）」，不再写「持续至战斗结束」。
- **【不屈】不动**：同为宝物词条但官方写「**本回合**受到所有伤害降低#3%-9%#」⇒ `hurt_stack` 语义（回合开始清零、最多 10 层），不吃这套清空。
- **验证**：新测试 `tests/treasure_jishi.test.ts`（5 例：3 层 = `sumReduce 0.15` / 受击后全部清空且 `status_expired` 计 3 / 不复活 / 新一轮恢复重新叠 1 层 / 反例守卫【不屈】不清零）；
  红灯证据：注释掉 `consumeNextHitReduce(ctx, target)` → `3 failed / 2 passed`；
  全量 `node ./node_modules/vitest/vitest.mjs run` → **100 文件 / 926 例全绿**（exit 0，golden 未变）；
  端到端 `scripts/_probe_tongchou_treasure.mts` → 「施加 3 次 / 受击后清空 3 层 / 残留 0」。
