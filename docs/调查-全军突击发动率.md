# 调查：「全军突击」发动率是否异常（100%）

> 起因：B 站评论反馈「全军突击发动率好像是 100%」→ 用户要求调查，并追加要求核对**包内的目标选取**。
> 日期：2026-10-16　手段：真引擎探针 + 数据/官方/构建产物三方对账 + 客户端配置表（`tb_cfg_skill*`）逐槽位比对

## 一、结论（先看这个）

**发动率没有 bug：官方、数据、引擎、线上产物四处一致，都是 35%（士气 120 → 39%）。**

| 口径 | 值 | 位置 |
|---|---|---|
| 官方技能页（当日抓取） | **发动几率：35%** | <https://stzb.163.com/jinenglist/200731.html>（移动版 `/m/skilllist/200731.html` 同） |
| 包内客户端数据 | `probability_init / probability_max = 35 / 35` | 客户端 `tb_cfg_skill` 行 200731 |
| 仓库战法定义 | `triggerRate: 0.35` | `src/data/skills.ts:4384` |
| 构建产物（本地 dist / 线上 Pages） | `triggerRate:.35` | `dist/assets/teamEditor-*.js`、线上 `battleSim-BJKyB1fU.js` |
| **真引擎实测（2000 场）** | **39.20%** | `scripts/_probe_tuji_rate.mts` |

实测细节：15,757 次判定 / 6,177 次发动 = 39.20%；`skill_trigger` 事件 `rate` 恒为 **39%**、`baseRate` 恒为 **35%**；`skill_cast` 6,177 次与成功次数完全一致（无重复释放、无隐藏判定）。

## 二、为什么「100%」在现有代码里出不来

能让显示值到 100% 的只有一条路：**「发动率提升」加算后封顶 100%**（`moraleTriggerRate` 的 `Math.min(1, …)`，`src/engine/action.ts:511`）。
全库只有 5 条 `trigger_boost` 定义：

| 战法 | 加成 | 过滤维 | 能惠及「全军突击」吗 |
|---|---|---|---|
| 难知如阴（法正） | +120% | `mainSkillOnly` | **不能** —— 全军突击是可学战法；`web/data/heroes.json` 的 169 名在库武将**没有**以它为主战法的（祝融夫人/钟会/许劭的主战法是火兽冲锋/举抑臧否） |
| 形兵之极 | +10% | `mainSkillOnly` | 不能（同上） |
| 动如雷震 | +100% | 仅追击 | 不能（全军突击是主动） |
| 形兵列阵 | +5% | 友军 · 主动/追击 | 能（+5%） |
| 侵掠如火（甘宁） | +20% | 自身 · 攻击类主动 | 能（+20%） |
| 宝物词条（机敏/英勇/筹算/熟虑…3%~30%） | 3%~30% | 全部限定**主战法** | 不能 |

外加田丰【尽言直谏】+10%（随机 2 个主动战法槽，可能抽中）。

**上限实测**：甘宁（自带 +20%）带全军突击 → 判定 11,351 / 发动 7,067 = **62.26%**，`rate` 恒为 62%（= (35+20) × 1.12 = 61.6 → 62）。再叠满形兵列阵 +5% 与尽言直谏 +10%，上限 ≈ 70% × 1.12 ≈ **78%** —— 结构上到不了 100%。

## 三、包内的目标选取（逐槽位核对）

`tb_cfg_skill` 里 200731 的**战法级** `target_description` 是 **`"0"`（未填）**；真正的目标写在**每个槽位**（`tb_cfg_skill_detail`）：

| 槽位 | effect | `target_type` | `attack_max` | 参数 | 语义 |
|---|---|---|---|---|---|
| 20073101 | 513 镇静（移除有害） | **-10** | **3** | — | 我方 3 人 |
| 20073112 | 301 攻击伤害 | **0** | **1** | `const=145`、`ratio=50`（1 级 72.5%） | **敌方单体**，伤害率 145% |
| 20073123 | 531 攻击伤害提高 | **-10** | **3** | `const=20 + 0.4×intel 20 = 28`、`available_hit=2` | 我方 3 人，接下来 2 次攻击 +28% |

`target_type` 取值规律（用全表共现反推）：`0` = 默认（按效果定义，攻击伤害即敌对）；负值/整十值 = 我方口径（并携带兵种/数量过滤）。同组对照：白刃 200691 的 101/102 段 = `-10/3`（我方），534 段 = `0/3`（敌我全体）；飒沓如星 200929 = `30/2`（我方骑兵 2）。

⇒ **包内明确：伤害段是「敌方单体」，与战法级「我军群体3」不是一回事。** 这一点此前在数据层没写出来。

## 四、已修：段级阵营缺失 → 解析模型把 145% 攻击段整段丢掉

**根因**：`web/roundModel.ts:493-496`

```ts
const side = (o.targetSide as string | undefined) ?? skillSide;        // 段没写就继承战法级
if (side === 'ally' || side === 'self' || o.target === 'self') continue; // 打友军/自身的伤害段跳过
```

全军突击战法级 `targetSide: 'ally'`，伤害段又没有段级 `targetSide` → 被当成「打友军的伤害段」丢弃。
修复前 `parseSkill` 实测 `segments: []`、只剩一条 `boostCaused 0.28` —— 即 L1/L2/L3 解析模型眼里它是「0 伤害的纯增伤战法」，而真引擎每场都打出 145%（damage 456~589）。

**修法（数据层按包内补显式阵营，不改模型语义）**：`src/data/skills.ts:4393`

```ts
{ kind: 'physical_damage', rate: 145, targetMode: 'random_single', targetSide: 'enemy' },
```

**验证（引擎行为零变化，模型恢复伤害段）**：

- 事件流 A/B（同 40 种子、逐字节哈希）：`e4cdbb91d8caa28704f443fbf8d112c65d07194f4b9a1b9042e5ac38be042c39` 改前 = 改后（全军突击 135 条 damage）；对照 四世三公 亦保持 `1363fa4071c227be821894a6b784e8bc957f1d54644d43ec6d335612605eeea5`
  （原因：`src/engine/action.ts:7746-7794` 里 `outSide==='enemy'` 与「无 outSide 但 outMode 有值」落到同一个 `skillTargets(enemies, outRange, outMode)`，池与排序完全一致）
- `parseSkill('quanjun_tuji')` 改后：`segments=[{kind:'physical', rate:145, targets:1, chance:1}]`
- `npx vitest run` → **96 文件 / 891 用例全绿**（golden 快照字节一致）；`tsc --noEmit` 仅 3 处既有报错（`tests/hot_preset_panel.test.ts:95-96`、`tests/rogue/save.test.ts:26`）

## 五、未修 / 待办

1. **四世三公（袁绍·汉 h6，`sishisan_gong`）**同样在解析模型里丢段（`segments: []`）。但它走 `attacker:'recipient'` 代打路径，实测给两个伤害段补 `targetSide:'enemy'` 会**改变引擎行为**（damage 事件 469 → 499，哈希变化）——需要单独评估，本轮已回滚。
2. 评论者看到的 100% 仍无法复现。可能：① 看的是别的判定行（战必断金等 `roundRepeat` 是 90%×1.12 → 封顶 **100%**，战报里会明写）；② 视频那一场带了加成（但上限 ≈78%）；③ 记错（官方页至今 35%）。
